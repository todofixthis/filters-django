# 001: Rely on the phx Plugin for ADR Tooling

## Context

`scripts/adr/generate_index.py` was ported from [`todofixthis/class-registry`][class-registry]
to index ADRs and validate their frontmatter, parsing it with PyYAML. An `adr_index`
autohooks pre-commit hook ran it whenever a commit staged an ADR, regenerating and staging
the index and blocking the commit on any fault; a CI job regenerated the index and failed on
drift. No ADR had been recorded yet.

[`phx:writing-adrs`][] now ships its own stdlib tool, [`adr.py`][], beside the skill. It
indexes, validates, scaffolds, supersedes, discharges and renumbers ADRs, and answers which
decisions bind a path. The phx plugin's hooks call it in Claude Code sessions: they inject
the decisions binding a file the first time a session touches it, regenerate the index after
a file-tool edit to an ADR, and report faults. They report only; none blocks. The tool also
installs as a `phx-adr` command, so CI can run it.

The two cannot run side by side. Each writes `docs/adr/INDEX.md` in its own format, so
`adr.py check` reports the repo generator's index as stale. And the plugin's hooks stay
silent unless the index's first line names `phx:writing-adrs`, which the repo generator's
header didn't.

The maintainer has made the phx plugin canonical for ADR tooling, and
[`.claude/settings.json`][] enables it for Claude Code sessions in this repository.

## Options

### Option 1: Do nothing

**Pros:** The pre-commit hook blocks a faulty commit for every committer.
**Cons:** The phx plugin's hooks stay off, and `adr.py` can't be used here without fighting
the repo generator over the index. The repo generator is a port that has to be kept in step
with the skill by hand.

### Option 2: The plugin's tool in sessions and in CI (Accepted)

Delete the repo tooling. Sessions get the plugin's hooks; a CI job runs `phx-adr check` from
the plugin at a pinned release's commit.

**Cons:** No local check blocks a commit; a fault from outside Claude Code is caught only once
pushed. Outside Claude Code nothing allocates a number or regenerates the index, so the author
runs `phx-adr` by hand. No stock Renovate manager recognises a `uvx --from git+…@sha` line,
so keeping the pin current needs a custom one.
**Risks:** Sessions load whatever plugin release is installed, not the pinned one. A release
that changes the index format leaves CI reporting the index stale right after a session
regenerates it, until the pin's update is merged; a merged update ahead of a session's
installed plugin does the same in reverse. An edit to the pinned line that breaks the
custom manager's match stops the pin moving without any error; the Dependency Dashboard's
detected dependencies are the only place the loss shows.

### Option 3: The plugin's hooks alone

**Pros:** Nothing to pin.
**Cons:** Nothing outside a Claude Code session with the plugin checks the corpus, and the
hooks only report, so a fault from any other commit lands on `develop` unnoticed. A commit that
rewrites the index's header line turns the hooks off without a report.

### Option 4: Vendor `adr.py` into the repository

**Pros:** A pre-commit hook could block faulty commits again, plugin or not.
**Cons:** A copy that drifts from the plugin, the maintenance cost Options 2 and 3 remove.

### Option 5: A pre-commit hook running the pinned `phx-adr check`

**Pros:** Blocks a faulty commit locally, with no vendored copy to drift.
**Cons:** Needs uv and, until cached, the network on every commit that stages an ADR. A
session on a newer installed release regenerates the index in that release's format, and
the older pin then blocks its commit, so pin skew stops work locally rather than only
turning CI red.

## Decision

Option 2. It keeps one implementation of the conventions, maintained with the skill that
states them, and keeps CI checking the corpus as the repo generator's job did. Option 3 would
leave a commit made outside Claude Code unchecked entirely. It matches [paddock's ADR 009][],
which made the same move.

## Consequences

- `docs/adr/INDEX.md` is generated by `adr.py` in the skill's format, which switches the
  plugin's hooks on here.
- `scripts/`, its tests, the `adr_index` hook (and with it `.autohooks/`), and PyYAML (the
  generator was its only user) are removed.
- The `adrs` job pins the 8.1.0 release's commit, with the version in a comment above it;
  `AGENTS.md`'s `phx-adr` commands read the ref from that job rather than repeat it. A
  `renovate.json` custom manager (`git-tags` datasource) matches the pair and proposes each
  new phx release, bumping version and commit together. Fix whatever the new release
  reports in that update's pull request.
- The plugin is Claude Code's, so an agent in another harness gets no session hooks, and
  meets the conventions only through `AGENTS.md`, the skill and CI.
